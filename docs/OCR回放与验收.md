# OCR 回放与验收

游戏截图、原始日志和玩家配置只保存在本机 `runtime/`，不随源码或发行包发布。离线回放不初始化游戏控制器，不产生鼠标键盘输入。

## 三类证据分别统计

1. **有独立标注的可读截图**：完整名称、等级、主副属性、数量和素材证据必须正确。用例配置 `required: true`；拒绝也算失败。
2. **应当拒绝的截图**：错误页面、被遮挡的关键字段、未完整显示的素材星级等。设置 `required: true` 和 `expected_rejection`，要求在指定检查上拒绝，不能用另一个偶然错误充当通过。
3. **尚未独立标注的历史截图**：用于发现裁切问题和模型分歧。历史 OCR 文字和新模型的输出都不能自动成为正确答案；这类结果不并入“准确率”或端到端成功率。

## 工具

- `tools/replay_enhancement.py`：调用生产原生解析器；比较已标注字段，核对材料星级，并检查已有成功样本不退化。
- 后台 `--replay-regions FRAME REGIONS_JSON MODEL`：输出指定裁切的原图和放大图读数；用于确认是裁切还是字段解析问题。
- 后台 `--replay-corpus JOBS_JSONL MODEL`：复用同一个包内模型批量回放，逐图输出结果，不创建游戏控制器。每行提供 `frame` 以及 `regions`、`request` 或 `kind: "filter"`。
- `tools/replay_equipment_ocr.py` 是旧 yas 配装布局回放；GOODScanner 配装解析应使用后台 `--replay-selection`，两者不要混作同一套验收。

## 修改裁切后的必查项

- 长名称、白色与灰色待激活文字、升级预览插行、结果箭头引起的数字左移。
- 数量栏 0–15 的不同字宽；不能因为有分母 15 就推测分子。
- 数字的首位、小数点、百分号和千位分隔符不能在裁切或清理中丢失。
- 同帧读数冲突继续拒绝，不通过多数投票选择期望数字。
- 背景粒子干扰时只允许受几何约束的图像预处理或重新读取完整画面，不替换 OCR 字符来“修正”数字。
- 素材栏横向滚动造成星级显示不完整时必须拒绝；不能用估计星级补足。

历史截图全部跑过，只证明回放覆盖了这些文件。发布前仍需记录明确的正负例结果、未知样本数量和剩余限制；离线 OCR 回放通过不等于新发行包已通过实机强化及换装验收。
