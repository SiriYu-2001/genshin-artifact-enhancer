# 库存导入与角色预设

1. 首次打开进入“库存导入”，选择 GOODScanner 导出的 GOODv3.json、其他 GOOD v1–v3 文件，或莫娜按部位分组的圣遗物 JSON。
2. 预览格式、五星数量、低星跳过数量及数据问题。没有错误后点击确认导入，不会启动游戏或 OCR。
3. 点击“下一步：角色与预设”，套用示例或编辑套装、主属性、平均词条权重和暴击率计分上限。
4. 使用“保存当前角色为预设”保存自己的用途。相同角色、相同用途更新原预设，支持删除。预设存在 SQLite，和某次库存分开。
5. 先只计算配装或查看霜／尘建议。导入后自动选中该库存，并取消“开始强化时重新扫描一次”；需要全新扫描时可自行勾选。

## 兼容与边界

GOOD 与 GOODScanner 的百分比单位是百分点（3.1 代表 3.1%）；莫娜使用比例（0.031 代表 3.1%）。程序按文件格式转换，不依靠数值大小猜测。

支持 GOODScanner 的 elixirCrafted（包括旧拼写 elixerCrafted）、unactivatedSubstats、totalRolls 和合法 initialValue。缺少定制标记、归属或第四词条时保留未知，不默认为普通／闲置或随机生成词条。rolls 等额外字段目前不参与算法。普通胚信息完整时可参与培养；定制保证状态不完整时仍需核验。

只保留规范化后的五星圣遗物数据；武器、账号 ID、成就等字段不落盘。低星按数量明确跳过，错误的五星会阻止整份确认，避免静默丢件。莫娜 omit 标记保留为计算排除，与游戏锁定标记分开。

重复属性的多件物品分别保留；无法区分的配装目标仍会被现有匹配规则阻止。重复导入同一份规范化数据复用原库存，不生成重复副本。库存保存于 runtime/imports，角色预设保存于 runtime/ui/workbench.sqlite3。

导入完成只表示文件已读取，不表示文件覆盖游戏全库。配装最优是相对于所选库存；游戏外改动后应重新导出或扫描。本版没有把扫描未完成判定放宽成成功，也没有承诺内置扫描已提速。

## 格式依据

- GOODScanner 固定核对提交 bffc4aad040eac0bb5f10c8b0b2ef86121fb29b5：[导出类型](https://github.com/Anyrainel/GOODScanner/blob/bffc4aad040eac0bb5f10c8b0b2ef86121fb29b5/genshin/src/scanner/common/models.rs)。
- [莫娜格式检查](https://github.com/wormtql/genshin_artifact/blob/main/src/utils/checkImportJson.js)与 yas 固定提交的 mona_uranai.rs。
- GOODScanner 使用的[公开名称映射](https://ggartifact.com/good/mappings.json)，核对日期 2026-10-05。运行时使用随包附带的映射，无需联网下载。

GOODScanner 可通过本地 API 扫描、管理和换装；本版只接入 JSON 文件。尚未接入它的扫描／换装 API，也没有找到可直接替代本项目逐阶段强化的公开接口。
