# 统一强化执行器与培养约束

## 执行器

扫描、穿戴和强化使用同一 GOODScanner 后台。后台复用上游 yas 系列的捕获、原生键鼠、OCR 模型池、背包定位与解析。评分、优先级分配和序贯决策仍由工坊的本地数学模块完成，不依赖 Agent。

强化通过受限 `/enhance` 协议执行 `open / inspect / step / reconcile / leave`，不暴露任意点击接口。`step` 是一次阶段放入与消耗确认，可能尚未到达下一个四级节点。策略层按实际结果重新判断。

当前等级和预览增量使用分离的区域；副词条按同一画面的标签和值识别，兼容素材预览引起的行位移。多个有效数字读数冲突时拒绝，不通过“改成最接近的合法值”强行匹配。数值裁切必须通过宽区域的同帧复核，防止截掉整数部分。

强化前验证：目标绑定、空素材栏、阶段放入、四星以下范围、五星快捷放入关闭及可见材料星级。来源明确的受限游戏自动放入是整批素材的依据；任意预先放入的素材不能继承这个证明。五星或未知星级始终拒绝。

消耗前先将请求及证据写入持久记录。请求超时、进程退出、观察失败时不重发消耗确认，必须核对结果。旧执行器的未确认操作不能直接迁移为新执行器的确认操作。

## 圣遗物额外充能下限

每个角色/套装需求可设置 `artifact_energy_recharge_min`，默认 0 表示关闭。单位为百分点，例如填写 60，要求五件圣遗物主、副属性合计提供至少 60% 额外充能。不包含角色基础 100%、武器、角色天赋、队友效果或套装效果。

这是整套配装的硬约束，独立于充能副词条的评分权重。即使充能权重为 0，配装也必须达标。优化器保留充能与评分、暴击之间的取舍，不能先按分数删掉所有高充能低分物品。

配装、序贯强化概率、霜尘单次收益、两次定制比较和长期预测使用相同约束。强化或资源建议的某一随机结果只有能组成满足约束的整套配装时才有提升收益。

## 建立起始套装

没有合格的完整 +20 基准时，工坊从现有库存搜索可培养的 4+1 组合。套装、主词条、借用与优先级规则继续适用，不虚构缺失部位。

起始套装搜索对升到 +20 后的完整组合进行模拟，包括暴击计分封顶、充能达标条件与初始三词条的已知第四属性。未达充能下限的模拟结果记为 0 分。初始数值使用当前观测允许的保守边界；未核实的定制保底状态不会被当作普通随机强化。

当前采用可复现的采样与有上限的组合搜索，选择已搜索组合中预期得分最高者。界面显示样本数、采样误差与是否触及搜索上限。它不是“平均属性代入评分”，也不保证真实期望的全局最优。即使完成组合遍历，也只证明该组采样目标下的最优。

选中的起始物品可继续培养至 +20，不会因缺少比较基准而被 5% 规则拦住。起始组合会被保存，先完成其中缺少的满级部位，避免尚未成套就反复追逐新的胚子；若被高优先级占用或发现不支持的定制状态才重新选择。一旦形成合法满级基准，恢复原来的序贯提升概率阈值。借用受限和其它高优先级的预留仍然生效。

## 启圣之尘：托底模型

参考玩家文章：[托底不抬天花板：圣遗物重塑的安全网模型与期望计算](https://bbs.nga.cn/read.php?tid=47452649)。该文的 `Y=max(X,k)` 与程序现有“剩余次数不足时才强制命中”算法，在指定两词条的总命中次数上等价。文章没有给出可独立验证的官方完整概率分布，因此这是明确标注的概率模型，不将“至少命中 k 次”的描述当作全部分布的证明。

在该模型中，初始四词条有五次随机强化，`X ~ Binomial(5, 1/2)`。对于保底 k=2、3、4，五次全部落在指定两词条中的概率均为 `1/32 = 3.125%`；不代表两条各自命中次数固定，更不代表强化档位全部最大。

普通、高阶、谕告重塑仍有不同收益分布：提高保底会抬升低命中结果，但不提高上述全中概率。初始三词条只有四次随机强化，k=4 时四次全中为 100%，不能套用五次全中的结论。

因此保持现有建议方式：计算相对合法库存最优配装的正提升期望、提升概率及单位尘收益，再按当前资源进度选择。保留旧结果、暴击封顶、充能约束和不同部位成本均计入。文章的单件平均词条期望可作分布校验，不替代个性化整套比较。

## 扫描、旧 JSON 与结束任务

首页按“库存 → 角色需求 → 运行”排列。默认使用已导入的库存，开始培养不会自动重扫。需要读取游戏时，“扫描当前筛选”保留用户筛选和排序条件；只有明确点击“扫描全部（清空筛选）”才清空筛选。当前筛选的结果仅代表本次读到的数据，不宣称全账号覆盖或全背包最优。

自动操作前检查游戏窗口及 1920×1080 分辨率，失败直接显示处理方法。导入和计算无需游戏窗口。

运行中每次鼠标、键盘输入及截图前检查游戏前台句柄；截图后再次确认焦点。失去前台立即取消本次原生任务，禁止继续向其他程序输入或识别其画面。界面提示切回游戏及对应入口；重新获得焦点不会自行恢复已取消的操作，未核实的消耗仍需先核对。

旧 yas／莫娜 JSON 缺少 elixirCrafted 标记时，不擅自认定为普通或定制物品。先按潜力安排只读核验，使用 GOODScanner 在游戏中确认实际来源。普通物品继续序贯培养；定制物品若缺少保底信息，单独暂缓，其余物品继续。缺少第4条属性的低级物品仍需扫描补全。

“结束本轮”和紧急中断立即阻止新输入，限时终止当前工作进程及其子进程，保存已有结果。每项任务还有独立停止标记，开始新任务不会重新激活上一项已取消任务。中断后可以导入、编辑、计算或开始另一轮；也可以明确选择继续上次进度。

如果中断发生在消耗已发送、结果尚未核对的时刻，保留待核对记录。界面显示“核对上次结果”，只读核对后才能再次强化或穿戴，不会因为超时再次点击消耗。旧的未完成任务不会伪装成成功。

## 识别流程与 GOODScanner 的区别

换装默认对每个角色只遍历一次，逐部位确认是否已正确装备、定位需要更换的目标，并在更换后当场生成属性与归属凭据。Python 调度器不再额外提交整套预检查和整套复查；只验证本次操作生成的凭据。缺少凭据不能判成功，也不能通过重发换装请求补救。额外整套只读复查仅在 CLI 显式指定 `--full-audit` 时运行。

名称和主属性标签不能精确匹配时，在同一帧的同一区域使用 GOODScanner 已打包的 PP-OCRv5 文字模型复核。该备用模型按执行线程延迟加载并复用；数字继续由快模型读取，不因名称失败而切换整页数字模型，不缓存旧帧的文字结果，不添加物品专用错别字替换。

当前固定版本的圣遗物通用与等级 OCR 默认均为 PP-OCRv6 tiny，模型池沿用历史 v4/v5 槽位名称；不能根据槽位名判断实际模型。背包扫描利用局部面板指纹等待加载、字段裁切、图标遮罩、数字局部放大和词条档位求解，并使切换物品与后台 OCR 并行。强化必须串行等待结果，且背景粒子、预览等级和待激活词条带来不同于背包的画面结构。

强化读取使用相同的截图、模型池和输入控制器；页面布局须单独校准。当前等级与金色预览等级分开裁切，数字读数不做字符串修补。整数等级在原图和灰度识别均失败时，按白色字形连通区域去除小粒子，再使用同一 OCR 模型；这一处理禁止用于带小数点的副词条。副词条按同帧标签确定布局，错误布局不重复推理空白数字区。每次有效观察必须来自一张完整画面，不跨帧拼接字段。

原扫描器的推测性兜底（例如为固定属性补出疑似漏掉的末位数字、无法读等级时默认 0）不作为强化身份依据。来源确认、真实属性和材料证明仍需通过校验。阶段放入只发送一次，随后限时等待非空材料栏；同一张合格画面同时提供目标与材料证明。空栏、身份变化、经验变化、筛选变化和无法识别分别报告，不再统称“目标变化”。失败保存原始失败帧、原始异常链和阶段读数，避免事后的另一次截图覆盖错误证据。

概率计算使用整数格点上的精确分布计数：每一维乘以分母的最小公倍数，将内部加法和哈希改为整数，最后还原分数；相同单次强化分布共享缓存。这不改变概率、阈值或决策，也不引入蒙特卡洛误差。此处与用于起始套装搜索的抽样模型不同。
