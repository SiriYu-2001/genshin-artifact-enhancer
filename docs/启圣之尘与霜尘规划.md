# 启圣之尘与霜尘规划

当前功能只提供建议，不操作重塑、强化、萃取、换装或消耗任何稀缺材料。页面为 `http://127.0.0.1:8766/#dust`；祝圣之霜页增加了整套目标与重塑替代对照。

## 界面怎么读

| 内容 | 含义 |
| --- | --- |
| 顶部尘图标和数量 | 当前拥有的启圣之尘；推荐页由用户填写预算 |
| 主属性 | 重塑不改变主属性 |
| 副属性左侧数字 | 该属性已经获得的强化命中次数，不是本次保底选项的权重 |
| 右侧选择圈 | 选定两个已有副属性，它们共享最低命中次数；不保证每条各命中一次 |
| 圣言解明进度 `a/6 → b/6` | 预览本次消耗后增加的进度；达到门槛的当次即使用增强保底 |
| 三个阶段节点 | 两次高阶之后，下一次升级成谕告；节点保底按3、3、4循环 |
| 底部“需要” | 花/羽1尘；沙/杯/头2尘，与祝圣之霜1/1/2/4/3的成本不同 |
| 保留原结果 / 保留重塑结果 | 两个方案只能保留一个；选择原结果也不退尘，进度照常推进 |

例如头冠需要2尘，`2/6 → 4/6`没有越过门槛，所以这一次仍保底2次。若前两个节点已经完成，则下一次从4点消耗2尘触发谕告，保底4次；之后阶段回到起点。数量按预算核算，例如10减2为8，页面不会替用户实际扣除。

## 精确区分三种保底

普通重塑：选定的两条合计至少命中2次。累积消耗每6个尘触发一次增强节点，前两个节点至少3次，第三个至少4次，然后循环。不是每重塑6次；沙杯头每次消耗2个尘，推进也为2点。进度是账号共享，可以跨物品与角色使用；没有定制的同套每版本两件限制。

状态保存为 `(points, phase)`，points为0–5，phase为本轮已完成的高阶次数0–2。一次成本c后：若 points+c<6，普通保底2；否则减去6点，按phase选择3或4，阶段前进。超过6的部分保留，例如5点消耗2尘变为下一阶段1点。

保底按“剩余机会必须全部命中才满足最低值”时强制落在所选两条。不是在保底之后额外追加随机强化。初始四词条拥有5次可重分配强化，即使保底4次，五次都落在所选两条的概率仍为1/32，不是50%。这条已经加入数学测试。

规则入口：[HoYoverse 官方帮助](https://support.hoyoverse.com/hc/en-us/articles/50333916291353-Where-can-I-find-the-rules-for-reshaping-with-Dust-of-Enlightenment)指向[官方玩法介绍](https://www.hoyolab.com/article/39387781)。结合[游戏提示文本的资料页](https://www.hoyodex.com/wiki/genshin-impact/artifacts)核对成本与阶段；跨线余点参照[玩家原始问答](https://www.reddit.com/r/Genshin_Impact/comments/1ugidgt/if_i_use_1_extra_dust_of_enlightenment_than/)，此次未实际消耗验证跨线余点。

## 重塑保留什么

四种副属性及其基础值保留，重新随机分配的是后续4或5次提升和增量档位。初始三词条在+4补出的第四条也保留；不会因为重塑变成初始四词条。不能把定制四词条1/3概率用于判断已有物品是哪种底子。

祝圣之霜定义的物品，重塑时保底副属性是定义时的两条，不能自由重选。库存只知道“定制件”但不知道锁定两条时，先列为待补录，不擅自把所有六种组合当合法。

机制参考项目 `SiriYu-2001/genshin-enlightenment-selection`，研究提交 `040b7e5b90a2c6d80e1992168cc484c662f3f697`。保留其末端保底、保留较好结果的思路；不沿用统一假设初值和基于比例的强化次数猜测。新计算使用实际四档内部数值、整套配装、暴击率上限与部位成本。

## 初始信息不全时如何计算

普通 yas 满级库存通常只有最终显示值，不能唯一恢复所有初始档位。因此：

1. 枚举每种副属性可解释当前数值的基础档位与强化次数。
2. 联合约束四个副属性的强化总数只能为4或5，排除不可能组合。
3. 当前实现将联合可行历史汇总为各词条初值上下界，再计算保守收益区间。这会丢失词条间的关联、使区间额外变宽；不为未知历史擅自赋概率，也不把区间中点当作精确估计。
4. 可以在页面补录从游戏确认的原始强化次数、初始档位及定制锁定词条，保存到 SQLite。补录值必须与最终属性的合法历史相容。

未知初值的区间可能较宽；按下界排序是保守选择，区间重叠不代表真实收益有确定排名。元数据按完整属性指纹保存。属性变化后需要更新；多件相同指纹的物品不能共享未经核验的底子记录。

普通件评估全部6个副词条对子，包含零权重词条。由于可以拒绝较差结果，某些高门槛下“有效词条＋无效词条”可能改变有价值的尾部概率，不能预先只取权重最高两条。[独立原作者分析](https://tooflesswulf.github.io/genshin-reshape-dumpstat/)展示了这种现象；本工具自行枚举，不把该结论变成固定口诀。

## 本项目使用的收益

保持旧配装是合法选项。一次重塑结果X的收益为：

    Δ = max(F(I替换该物品为X), F(I)) − F(I)

F为符合指定主属性、4+1、暴击率计分上限、借用和优先级限制的整套最优分数。旧物品和重塑结果是同一物品的两个版本，不能同时装备。结果包括提升概率、期望整套提升、每尘期望提升，以及假设处在3/4次保底时的条件收益。

页面当前保底由账号状态与本次成本决定。未来保底列只作比较，不是可自由切换的操作选项。停止培养、垫保底和未提升的重塑也有资源机会成本；当前模块未求出全部预算跨物品动态最优方案。

## 对NGA方案的采纳与区别

参考[这篇NGA主楼](https://bbs.nga.cn/read.php?tid=46822657)，作者“亿个客户”，2026-05-21。可读内容将随机刷取、定制、重塑分开比较，强调可自定义权重、目标分数及坏底子与歪强化的区别。

“圣遗物价值的意义”和“为什么建议手动选择目标分数”两处折叠正文在保存HTML中为空，所以本实现没有宣称复现其价值函数，也不把作者示例中的220分直接搬入平均词条计分。

已经采纳：

- **换胚与重塑并排比较**：祝圣之霜页可勾选“同时对照现有底子的重塑收益”。同一库存、同一目标、同一优先级规则下，对比单次定制与单次重塑；霜和尘分别计成本，不默认1:1兑换率。
- **共享整套目标分数T**：两页都可填写目标，增加达标概率及“目标内收益”排序。
- **明确底子限制**：若即使理想重塑也不能改善整套，乐观上界剪枝为零；定制会产生新底子，重塑则不会更换四种副属性。

本项目明确采用的目标价值为 U(S)=min(S,T)，目标内收益为：

    E[max(U(S_new) − U(S_old), 0)]

它只计算达到目标之前的改善；超额提升仍计入普通期望得分，但不在目标内收益里继续加分。达标概率按整套分数≥T计算。没有目标时保持原来的原始期望与单位成本评分，不改变已有配置。这个函数是本项目的透明设计选择，不是未经取得正文就假称还原NGA公式。

“刷多少件才能出更好”通常依赖自然掉落的尾概率、来源和部位概率，可以作为稀有度指标，但不能直接代替定制/重塑的边际收益。长期刷取对照见《长期资源策略与数学模型》；不同资源不使用虚构统一价格。

## 独立运行与验证

新模块仍由本地Python计算，网页只收集参数和显示结果；没有LLM中间决策、模型API、Computer Use或重塑执行入口。`tools/verify_standalone_elixir.py --kind dust` 可执行与霜模块同样的独立副本、环境清理、外网/原目录/SDK访问阻断、两次冷启动和结果校验。

测试覆盖截图状态2→4→谕告、3/3/4循环、成本与余点、合法历史推断、定制锁定对子、非法补录拒绝、六对子枚举、目标截断、配置持久化和只读worker。独立副本的两次计算结果一致；私人库存和明细仅保存在runtime。
