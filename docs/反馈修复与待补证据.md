# 配置、中断与离线包反馈

## 已修复并加入回归的情况

- 浏览器草稿引用的配置 ID 在数据库中不存在：保留完整表单，保存为新配置；已主动删除的配置不能被旧页面自动复活。
- 浏览器缓存现在按数据库身份隔离。新数据库不继承同一路径或同一端口下旧数据库的配置 ID。
- 工作进程退出，但其后代占用 stdout：结束状态以进程退出为准，不无限等日志管道关闭。
- 停止操作分别跟踪工作进程和本包后台，页面区分正在停止、停止完成、退出失败。终止后台必须同时验证程序路径和实例启动参数。
- 旧任务的结束回调不能取消新任务；已被中断的新任务不能自行清除中断标记。
- 已退出的旧霜华控制器留下 running 状态文件时，不再把文件当成活进程一直等待。
- JSON 导入按钮在任务运行/退出期间解释为何暂不可用，停止后恢复。
- 扫描 90 秒没有新增识别结果时主动停止后台，保留诊断，不发布不完整库存。
- 启动时检查离线包缺失/混装文件，页面显示版本与执行器。不下载依赖，不回退到本机外部插件。

## 仍需原始证据的情况

### v0.1.7 预览版：当前筛选扫描与散件提示

当前筛选扫描保留了游戏筛选，但接入层仍沿用了全库扫描的配置，关闭了空位／可见末页检测。因此页首全库数量被当成扫描目标，既显示错误进度，也可能在实际列表结束后继续点击。修复后筛选模式开启已有的空位和滚动末尾判断，全库数量仅作为安全上限，不阻止提前到达真实末尾；不利用图标相似性跳过可能真实重复的圣遗物。全库扫描保留原有数量核验。

运行页面显示“当前筛选已检查 N 件，总数将在列表末尾确定”，不再把右上角全库数写成筛选结果总数。保存的筛选库存仍明确标为 `observed_filter_results`，不能冒充完整账号库存。

4+1 方案允许一个其他套装的散件。候选来自“天之美赐”时，自动定位会筛选其真实套装，即使角色方案要求四件“影中沉凝的幻灭”；这是预期行为。新增定位提示显示目标套装并标注“散件候选”，评分、配装约束及概率阈值不变。根据反馈者补充，本次没有证据表明套装识别发生误选，因此没有修改套装选择算法。

验证：Python 242 项中 241 通过、1 项符号链接权限跳过；原生 Workbench 测试 24 项通过，包含筛选／全库策略分离；原有背包空位与滚动判断测试 14 项通过（与前组有重叠）；DOM 验证筛选总数不显示全库数、散件定位提示，以及原有操作流程。补丁从修改前源码重放得到一致结果。未进行本版真实游戏筛选扫描验收，本修复随 v0.1.7 预览包提供，v0.1.6 不包含此修复。

### 已定位：`Stage preconditions not met`

一组原始失败图经包内生产 OCR 回放确认：前两次界面为“快捷放入”与“5星及以下素材”，第三次改为了“阶段放入”，但素材筛选仍为“5星及以下素材”。等级和素材数量均识别正确。这是实际设置不满足要求，不是该组画面的裁切或 OCR 失误；程序应停止，不能跳过五星素材保护。

操作前请将强化页的素材下拉框设为“4星及以下素材”，在放入设置中使用阶段放入并关闭五星素材，保持素材栏为空。无需重新扫描库存。源码现已分别报告满级目标、非空素材栏、未确认阶段放入、未确认四星及以下筛选，并在原始错误中保留同帧读数；未识别通过不等于断言用户设置错误。旧后台的笼统报错显示完整检查清单。

这项改动只改善前置检查的诊断，四项通过条件及确认前的素材星级检查不变。原始玩家截图不进入公开仓库。

### v0.1.6 预览版：自动准备阶段放入

后续五张反馈画面中，四星及以下筛选、目标等级和空素材栏均符合要求，唯一缺失的是阶段放入。已发布的 v0.1.5 可以明确提示，但仍需用户手动打开游戏齿轮中的“开启阶段放入功能”。旧格式日志不能单独证明用户当前运行的版本，也可能来自历史失败记录。

v0.1.6 允许在完整目标身份、未满级、空素材栏、四星及以下筛选均通过后进入放入设置。核实标题、两个设置标签、开关位置及五星素材关闭状态，阶段开关明确关闭时仅点击一次；已经开启时直接保留。随后读取新帧复核阶段已开、五星仍关闭，再返回强化页重新核实完整目标和全部前置条件。无法读清、未生效、中断或五星开启均停止，不重复切换，不放入材料，不点击五星开关。

失败时额外保存 `settings-observations.json` 与对应原始帧。设置弹窗回放与确定性状态测试不等于真实游戏点击已经验收；本改动随 v0.1.6 预览包提供，v0.1.5 仍需手动开启。

离线验证：68 张强化画面字段匹配，已有样本无退化；465 张历史设置弹窗均读为阶段已开、五星已关，6 张错误页面被拒绝。19 项原生强化测试覆盖开关已开、关闭后仅切换一次、未生效、未知状态、五星开启和中断；关闭态操作通过状态模拟测试，尚未完成新的实机开关点击验收。Python 回归 240 项中 239 通过，1 项因 Windows 符号链接权限跳过。

网页显示“阶段放入后的画面无法完整识别”只能证明程序没有确认强化，不能确定失败字段。需要对应的游戏原始 `frame.png`、`error.json`，有的话再加 `stage-observations.json`。网页照片不能用于 OCR 回放。

“到底还一直点”需要确认发生在套装名称筛选列表，还是圣遗物卡片扫描列表。提供版本、任务 `stdout.log` 和停止前的游戏页面。当前扫描器已有滚动位置/末页检测；新增无进度停止只是避免卡住，不能代替对具体漏检原因的诊断。

旧日志出现“启动包内霜华与 yas”不符合当前默认 GOODScanner 链路。需核实实际运行的 EXE / 页面底部版本，不能只凭下载过新版判断运行版本。
