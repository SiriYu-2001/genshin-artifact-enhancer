# 祝圣之霜页面

该模块使用本地脚本计算，可独立于 Agent 运行；有效库存与已保存角色配置是其输入。

打开 `http://127.0.0.1:8766/#elixir`，或从左侧选择“祝圣之霜”。先在培养配置中保存角色、套装、主属性、权重与暴击率计分上限，再在本页选择角色/用途和库存快照。单角色模式使用当前目标；多需求模式可以切换已有需求。

## 参数与结果

- 霜预算：0–999 的整数，不要求全部花完。
- 每套剩余次数：0、1、2，用户按游戏实际状态填写。同套装的多个角色/用途共享这项设置；计算不会扣次数或扣材料。版本刷新后手动更新。
- 最低提升：以平均词条分计。成功概率为超过该值的概率；期望提升仍统计所有正提升。
- 优先目标：成功概率、平均整套提升、每霜收益，三个指标各显示一张推荐卡。
- 遵循配置优先级/场景：使用既有分配规则预留更高优先级、同时使用的配装；关闭则独立计算当前角色。是否允许借用仍遵循培养配置。

定制初始四词条固定用 `Fraction(1,3)`，初始三词条用 2/3，与秘境掉落的 1/5 分开。页面不提供将其改成 20% 或 34% 的开关。外部原作者计算器的[假设表](https://www.brandonfowler.me/artifact-odds/assumptions/)也区分 domain 20% 与 crafting 33.33%；这是社区模型依据，不应描述为官方服务端概率披露。

计算前保存本轮配置副本，运行过程中更改表单不会改变正在计算的输入。参数、草稿和配置版本继续存入 `runtime/ui/workbench.sqlite3`，每轮完整结果和日志存入 `runtime/ui/jobs/<id>/`。页面显示本次结果所用预算、次数、阈值、基准与库存日期。改变规则后须重新计算；只切换排序目标可直接查看同轮结果。

最近一次成功建议通过 `/api/elixir/latest` 恢复，即使其后又做过其他类型任务，也不会丢失。导出按钮生成含推荐、约束与来源信息的 JSON。

## 计算范围

单次穷尽合法指定词条组合，按实际档位与保底状态枚举；两次对每部位的单次高期望候选做 20 万组联合配装模拟。预算或次数不足时不会推荐不可执行的方案。两次模拟另显示统计误差，不宣称全部自适应策略的最优性。

计算基准是库存中已确认的 +20 圣遗物。没有完整可行基准、不借用模式下装备归属已过期时，明确报错。支持 4+1、散件位置变更、主属性占用暴击率上限。实际定制前仍应确认套装已开放定制以及余额、次数输入正确。

长期策略说明保留在页面折叠区，但本页数值尚未加入未来掉落或启圣之尘。做完第一件后更新库存再算第二件。页面没有自动制作、萃取、强化或换装按钮；后台 elixir 任务也不会启动管理员控制器。停止计算只结束计算进程，带任务 ID 核验，不能误停其他窗口后来启动的游戏任务。

## 验证

数学测试明确检查 `2/3 × 初始三词条结果 + 1/3 × 初始四词条结果`，并确认不等于使用秘境 20% 的混合。另验证预算、次数、参数持久化、优先级预留、过期归属拒绝、只读 worker、限定任务停止和最近结果恢复。

页面使用 JSDOM 执行真实前端逻辑，验证编辑、保存、请求分发、结果与概率显示、文本转义和历史恢复，不使用浏览器/Computer Use 自动化。最后通过真实本地 HTTP 接口启动只读计算，核验结果可在页面和重启后恢复。该验证不操作游戏或消耗任何资源。
