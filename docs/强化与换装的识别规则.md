# 强化与换装的识别规则

## 从实机失败得到的结论

2026-09-25 的强化完成了 122 次单件流程，自动换装随后启动，却因角色名被读成“桑多涅0”而停止。9 月 28 日复查保存的截图，确认识别框包含右侧 Q 键提示。缩小区域后，再处理分隔符和边缘标点，本轮 8 个目标角色的历史画面全部识别通过。这个结果只验证这些保存的画面，不代表全部界面都已通过实机验证。

其他日志包括：标签带引号或句点、经验分母丢位、副词条被动画遮挡、列表到底后仍重复扫描、控制进程退出。它们不能统一解释为“OCR 模型差”，也不能用同一个无限重试解决。

另一个可复现问题是短行右侧留白过多：“生命值+239”在清晰画面中仍被读成“生命值+2a9”。切换现有模型、灰度化和颜色过滤未能稳定解决。最终按文字像素的连续范围收紧右边界，保留原像素，再交给同一 yas OCR。34 张成功及失败画面的完整物品属性回放全部通过。这是选定回归样本的结果，不能写成全库识别准确率 100%。

## 统一处理方式

| 情况 | 应采取的动作 | 不能采取的动作 |
|---|---|---|
| 标签边缘标点、已知简繁字形 | 只对标签做规范化，再检查完整标签 | 修改数字、删除名称中的字母或数字 |
| 动画干扰、短暂漏字 | 等待并重新读取完整画面，次数有上限 | 拼接不同帧的若干字段，凑出期望答案 |
| 数值能解析但不合法 | 用等级范围、合法词条档位、实际跨越节点数拒绝该读取，再重读 | 把不可读值默认为 0，或猜一个最接近的数值 |
| 相似套装名称 | 用相似度提出一个筛选候选，再核对选中后的完整大标题 | 用模糊相似度直接确认装备或消耗 |
| 列表位置改变 | 先试缓存位置，完整属性不符时重新定位 | 仅凭旧格子位置执行装备 |
| 滚动到达底部 | 检查滚动条是否移动 | 用含动画噪声的整段 OCR 文本变化判断翻页 |
| 页面丢失 | 停止当前页面上的坐标操作，有限次数恢复已知入口 | 在大世界继续点击角色页坐标 |
| 控制器断连 | 报告连接问题，恢复控制器后核对当前状态 | 当作 OCR 错误无限重读或重发消耗动作 |
| 点击强化后结果未确认 | 保留 pending，只读结果，确认进度后才能继续 | 因超时再次点击强化 |
| 材料包含五星或星级不明 | 停止确认 | 降低识别要求、猜低星或回退到五星素材 |

## 让 OCR 做必要的工作

页面导航由脚本维护状态，固定控件采用已校准的位置，翻页依据滚动位置。OCR 主要承担角色身份、目标圣遗物完整属性、必要的数值及操作结果核验。

全库扫描继续使用 yas 的圣遗物专用识别能力；自定义界面区域通过 yas 适配的 PP-OCRv5 读取。同一个引擎在不同字体、背景和裁切上的误差可能不同，应分区域测量。

物品身份使用套装、部位、星级、等级、主属性类型和全部副属性。缓存只是定位提示，不能代替身份。已装备的项跳过；实际换装后检查目标属性、装备归属和卸下按钮，再核对当前角色。

经验读不清时保留未知。如果等级已增加，可以依据等级和合法词条变化证明进度；等级没变且经验未知，则不能证明进度，更不能重复消耗。五星材料禁令始终独立于识别容错规则。

## 已落地的代码

- `recognition.py`：按字段白名单在读取入口统一处理标签，保留原始 OCR 记录和所有数字、材料证据；标签边缘处理、标签比较、只读验证与有限重读；完整单帧通过才接受。读取连接异常不混入 OCR 重试。
- `Navigation.observe_validated`：记录每次接受、重读和失败的原因及画面目录，写入 `runtime/recognition.jsonl`。
- 强化：共享读取入口；进入强化页时把标题、等级、词条一起纳入重读校验。原有合法词条增量检查和 pending 记录保留。
- 换装：角色裁切排除 Q 提示；标签规范化；疑似目标先重读；页面丢失不再继续盲点；缓存位置后仍核对完整属性；滚动条判断到底；装备者重读；每完成一个角色立即保存进度。

## 验证方法与边界

优先用失败时保存的截图离线回放同一个 yas 引擎，区分裁切、模型识别和解析错误。再用测试验证错误数据不会被当作正确身份或安全材料，最后在游戏中验证整个状态转换。

公开版本包含离线测试，不发布私人画面、库存或实机验收记录。单元测试通过不代表所有游戏页面均已实测。

后续应持续记录首读通过率、重读次数、单件定位时间和明确的失败类别。测试集应覆盖不同角色背景、动画阶段、首尾页、满级与未满级，而不是只保留几张成功图片。更换 OCR 模型只有在相同裁切和同一批回放样本上能稳定改善结果时才有依据。


## 冻结版本验收

`tools/accept_equipment_run.py` 记录 Python 代码、布局、yas 适配二进制和配装库的校验值，再自动串行执行两轮完整换装。每轮必须按顺序核验全部角色、每人五个部位，且没有物品冲突；第二轮不得再次换件。期间源码或配装库改变，或者任一任务报错，都判失败，保留具体记录。脚本不会在失败后擅自重做操作。

这个标准把“开发时曾经成功操作过”与“固定版本独立完成全流程”分开。首轮验收曾在尼可的最终复核中失败；该失败记录保留，不能计入通过次数。
